# 套餐额度消耗倍率

## 目标

让周期额度套餐支持可配置的额度消耗倍率。管理员可以在套餐用量权益里设置“套餐消耗倍率”，控制用户请求消耗套餐额度的速度。

这里的倍率定义为：`1 美元模型基础价需要消耗多少美元套餐额度`。

## 非目标

- 不改变模型基础价格、上游成本倍率、钱包销售倍率的定义。
- 不把套餐消耗倍率和产品策略销售倍率合并。
- 不自动修改用户已经购买或已经发放的历史套餐权益。
- 不改变钱包赠送、会员分组、套餐购买限制和套餐续费规则。

## 行为变化

### 套餐模板

套餐用量权益新增 `quota_multiplier` 字段，默认值为 `1.0`，必须大于 `0`。

字段只属于用量额度权益，钱包赠送和会员分组不使用这个字段。

### 套餐快照

用户购买套餐或管理员发放套餐时，当前套餐模板里的 `quota_multiplier` 会写入用户套餐权益快照。

套餐模板后续修改倍率，只影响之后新购买或新发放的套餐；已持有套餐继续按自己的快照倍率结算。

历史套餐快照没有 `quota_multiplier` 时，按 `1.0` 处理。

### 预检查

请求开始前检查套餐额度时，不能再直接比较“剩余额度”和“预计基础价”。

系统需要先计算套餐能覆盖多少基础价：

```text
可覆盖基础价 = 剩余套餐额度 / 套餐消耗倍率
```

如果用户有多份可用套餐，每份套餐按自己的倍率计算可覆盖基础价，再汇总判断。

### 最终结算

请求结束后按真实基础价结算：

```text
套餐扣除额度 = 套餐覆盖基础价 * 套餐消耗倍率
钱包扣除金额 = 未被套餐覆盖的基础价 * 产品策略销售倍率
```

套餐额度账本继续记录“扣了多少套餐额度”，即 `entitlement_usage_ledgers.amount_usd` 不改语义。

使用记录继续从结算账本和钱包扣款拆分展示费用。单份套餐时可以展示实际套餐消耗倍率；多份套餐倍率不同且同一请求同时消耗多份套餐时，列表展示合并后的平均消耗倍率，明细对账以 `entitlement_usage_ledgers` 为准。

## 影响范围

- 后台套餐管理表单、校验、接口类型。
- 套餐创建、更新、购买、后台发放快照。
- 套餐权益解析函数。
- 请求前余额和额度预检查。
- Postgres、MySQL、SQLite 三套最终结算实现。
- 管理端和用户端使用记录的扣费拆分展示。
- 钱包记录里的扣费拆分展示。

## 验证方式

- 后端测试覆盖默认倍率 `1.0` 的兼容行为。
- 后端测试覆盖套餐倍率小于 `1`、大于 `1`、套餐不足后钱包补扣。
- 后端测试覆盖历史重叠权益存在时的倍率计算；新购买和新发放仍只允许一个有效套餐。
- 前端测试覆盖套餐表单默认值、校验和提交 payload。
- 使用记录测试覆盖套餐倍率不再写死 `1.0`。
