# 管理端套餐额度可见性

## 目标

- 管理员在用户列表直接看到当前生效套餐、当前额度周期的已用和剩余额度、套餐到期时间及下次刷新时间。
- 用户在套餐中心看到当前套餐每日额度的已用、剩余和下次刷新时间。
- 所有时间与额度都由服务端按实际计费窗口计算，前端只负责显示。

## 非目标

- 不改变额度周期长度、套餐价格、有效期、购买流程或扣费顺序。
- 不修改历史套餐和历史用量。
- 不在本次改动中将滚动 24 小时窗口改成自然日零点刷新。

## 行为变化

### 管理员用户列表

用户列表接口为当前页每个用户增加 `plan` 摘要：

- `entitlement_id`：当前生效的用户套餐记录。
- `plan_id`、`plan_title`：套餐标识与名称。
- `starts_at`、`expires_at`：套餐有效期。
- `quota_total_usd`、`quota_used_usd`、`quota_remaining_usd`：当前所有额度限制共同决定的实际可用额度。
- `daily_total_usd`、`daily_used_usd`、`daily_remaining_usd`：当前滚动 24 小时额度；套餐没有每日额度时为 `null`。
- `daily_window_started_at`、`daily_window_ends_at`：当前每日额度周期及下次刷新时间；套餐没有每日额度时为 `null`。

页面增加独立“套餐”列。无生效套餐显示“无套餐”；有每日额度时显示套餐名称、“今日剩余 / 总额”和下次刷新时间；其他周期额度更严格时，另行显示“当前剩余”，不能用实际可用额度替换今日剩余；只有周或月额度时显示当前剩余额度；没有用量额度的会员套餐仍显示套餐名称并标注“无每日额度”。额度为零时使用警示色，但状态仍与钱包分开。

### 用户套餐中心

`GET /api/billing/entitlements` 在现有套餐列表之外返回 `quota_summary`。套餐卡片显示：

- 今日剩余额度与总额。
- 今日已用额度。
- 其他周期额度更严格时，单独显示全部限制共同决定的当前剩余额度。
- 下次刷新时间。
- 套餐到期时间继续使用现有字段。

没有每日额度的权益不显示每日刷新信息；接口暂时不可用时保留套餐基本信息，不在前端猜测额度。

## 窗口语义

当前系统的每日额度是从套餐生效时间开始计算的滚动 24 小时窗口，不是自然日。`daily_window_ends_at` 是服务端实际用于计费的下次刷新时间。界面必须显示这个准确时间，不能按客户端时区自行计算零点。

同时存在日、周或月额度时：

- `daily_*` 只表示每日窗口。
- `quota_remaining_usd` 表示全部额度限制共同作用后的实际可用余额，避免月额度耗尽时仍显示可用。

### 与实际扣费保持一致

页面不能根据套餐开始时间单独重新计算额度周期。每种额度如果已经存在尚未结束的数据库窗口，页面和扣费都直接使用该窗口保存的开始时间、结束时间和已用金额；只有窗口不存在或已经结束时，才按套餐开始时间计算当前周期。

管理员修改套餐开始时间不会清空尚未结束窗口的已用额度。修改后页面继续显示扣费系统实际使用的窗口，直到该窗口结束，避免出现“页面显示有额度、请求实际不能使用”的不一致。

## 性能与一致性

- PostgreSQL、MySQL 和 SQLite 都使用当前页用户 ID 批量读取生效套餐和当前额度窗口。
- 套餐批量查询与现有认证、钱包、用量和用户组查询并行执行。
- 数据库查询次数不随当前页用户数量增加；禁止前端逐用户请求套餐接口。
- 正常情况只读取每个套餐当前的日、5 小时、周和月窗口，不汇总全部历史扣费明细。
- 当前额度窗口没有记录时，直接按当前周期已用 0 处理；请求准入、管理员列表和套餐中心都不查询历史扣费明细。
- 金额按服务端现有精度计算，前端只格式化显示。

## 读取失败

额度摘要是套餐基本信息的附加数据，读取失败不能使整个套餐中心或管理员用户列表返回错误：

- 用户套餐接口继续返回生效套餐，并返回 `quota_summary_status: "unavailable"`。
- 管理员用户列表为当前页用户返回 `plan_summary_status: "unavailable"`。
- 前端明确显示“额度暂时无法读取”或“套餐信息读取失败”，不能将失败误显示为“无套餐”。
- 服务端记录带用户范围的错误日志，供监控报警使用。

管理员发放、修改或取消套餐成功后，用户列表立即重新读取，不保留旧的套餐列内容。

## 影响范围

- 套餐数据契约与 PostgreSQL、MySQL、SQLite 批量读取。
- 管理端用户列表接口和表格。
- 用户套餐权益接口和套餐中心。
- 中英文界面文案与相关测试。

## 验证方式

- 有生效套餐的用户在用户列表看到套餐名称、剩余额度、到期和刷新时间。
- 无套餐、未开始、已过期或已取消的套餐不作为当前套餐显示。
- 每日额度部分使用后，已用、剩余和下次刷新时间与计费窗口一致。
- 日额度耗尽时显示 0，不出现负套餐余额。
- 用户套餐中心与管理员用户列表对同一用户显示相同额度和刷新时间。
- 用户列表一次返回多名用户时只执行一次套餐摘要批量查询。
- 已产生用量后修改套餐开始时间，页面仍与实际扣费窗口一致。
- 无论当前额度窗口是否存在，都不扫描历史扣费明细；没有记录时显示当前周期已用 0。
- 额度摘要读取失败时，套餐基本信息和用户列表仍可打开，并明确显示读取失败。
- 发放、修改和取消套餐后，管理员用户列表立即显示新状态。
- 后端相关测试、前端测试、类型检查和生产构建通过。
