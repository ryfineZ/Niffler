# 号池账号测试与 Codex 额度重置

## 目标

- 在号池管理账号列表直接发起单账号测试，复用现有直连测试请求和结果展示。
- 在 Codex 账号额度区域显示主动重置次数，并允许管理员消耗一次重置额度。
- 重置成功后立即刷新上游额度，并解除该账号因额度限制产生的本地冷却。

## 非目标

- 不移动、合并或修改账号权限、代理、编辑、启停、删除等现有操作。
- 不增加批量重置、自动重置或定时消耗重置次数。
- 不改变普通业务请求的调度、计费、限速和失败切换规则。
- 不把本地清除冷却伪装成上游额度重置。

## 行为变化

1. 号池账号列表增加“测试账号”入口，测试请求携带指定账号 ID，只使用该账号，不触发账号池切换。
2. Codex 配额刷新从 `wham/usage` 读取 `rate_limit_reset_credits.available_count`，并写入现有额度快照。
3. 管理接口按账号调用 Codex 上游 `rate-limit-reset-credits/consume`。同一次操作使用稳定的幂等键；重试时不得生成新键。
4. 上游成功响应 `ok` 归一化为 `reset`；兼容的 `reset` 和同一幂等键对应的 `already_redeemed` 也视为成功。`nothing_to_reset` 和 `no_credit` 返回明确结果，不清除本地状态。
5. 重置成功后清除该账号及其模型的号池运行时冷却，再刷新额度快照。用户手动设置的启停状态、优先级、代理、权限和自适应限速学习结果保持不变。
6. 如果上游已经完成重置但后续额度刷新失败，接口仍明确返回“重置已生效”，前端不得引导管理员使用新幂等键立即重试。
7. 桌面端和移动端号池列表都提供测试入口；Codex 重置入口紧邻账号额度及剩余重置次数。所有新增操作覆盖不可用、处理中、成功和失败状态。
8. 账号测试准备期间如果切换服务商，丢弃旧服务商的异步结果并关闭旧测试状态；新增错误提示同时提供中英文文案。

## 影响范围

- Rust 网关：Codex 配额解析、上游重置请求、单账号管理路由、运行时冷却清理和额度刷新。
- Vue 前端：号池账号类型、测试入口、Codex 重置次数与重置反馈。
- 数据存储：沿用 `upstream_metadata` 和 `status_snapshot.quota` JSON，不新增数据库字段。

## 验证方式

- Rust 单元测试覆盖重置次数解析及四种上游结果。
- 网关测试覆盖新管理路由的分类、幂等键请求体缓冲和上游结果解析。
- 前端测试覆盖号池列表入口、测试账号 ID、重置次数、重置按钮状态和请求参数。
- 运行相关 Rust 测试、前端类型检查、Vitest 和界面审查。
