# 用量正文保留与去重整改

## 目标

降低请求/响应正文写满数据库磁盘的风险。默认情况下只保存用量、计费、路由和错误摘要，不保存完整 HTTP 正文；只有显式配置为完整记录时才保存正文，并限制单个正文大小。

## 非目标

本次不做跨请求正文哈希去重，不改 `usage_body_blobs` 表结构，也不迁移历史正文数据。跨请求去重需要新增内容哈希、引用计数和清理语义，风险高于本次止血需求。

## 行为变化

- 缺少 `request_record_level` 或旧配置 `request_log_level` 时，默认按 `basic` 处理，不保存请求或响应正文。
- 显式配置为 `full` 时，单个请求正文和响应正文默认最多保存 256 KiB，超过后只保存截断摘要。
- 自动清理默认更积极：详细正文保留 1 天，压缩正文保留 2 天，HTTP 头保留 30 天，用量摘要仍保留 365 天。
- 同一次请求内，如果 `provider_request_body` 与 `request_body` 内容相同，只保留 `request_body` 的正文引用，`provider_request_body_ref` 复用同一份正文。
- `enable_usage_detail_cleanup` 单独控制用量请求头、请求体、响应体及其父用量记录的自动清理，默认开启。设为 `false` 时，后台仍会按配置清理过期 Key、审计日志、请求候选和节点指标，但不会自动删除用量明细或承载这些明细的父记录；管理端手工清理仍然有效。
- 流式完整记录优先写入对象存储。对象存储没有配置或写入失败时，改为保存内存缓冲：未超过上限记为完整正文，超过上限记为截断正文，不因对象存储不可用而丢掉已经捕获的内容。

## 故障诊断保留模式

需要保留可逐字复核的请求和响应时，同时设置 `request_record_level = "full"` 和 `enable_usage_detail_cleanup = false`。该组合会保留客户端请求体、最终上游请求体、上游响应体、客户端响应体及 HTTP 请求头；`X-OpenAI-Actor-Authorization` 不在默认敏感请求头清单中，因此按原值保存。认证令牌等默认敏感请求头仍按现有规则遮盖，不影响核对图片工具声明和响应事件。

## 影响范围

影响网关用量记录、后台用量清理任务、管理后台查看请求审计正文的可用性。计费、用量聚合、路由快照和错误摘要不依赖完整正文，不应受影响。

## 验证方式

- 覆盖缺配置默认 `basic`、显式 `full` 使用新的正文大小上限。
- 覆盖清理任务默认保留期。
- 覆盖关闭 `enable_usage_detail_cleanup` 后只停止用量明细及其父记录自动清理，不停止过期 Key 和其他后台清理任务。
- 覆盖流式正文对象存储不可用时回退到受大小限制的本地记录。
- 覆盖同请求内重复请求正文只生成一份正文引用。
- 运行相关 Rust 单元测试。
