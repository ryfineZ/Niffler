# 全局失败换号与号池容量异常

## 目标与非目标

面向管理全站账号的管理员：正常请求默认具备输出前容量容错能力；在现有按提供商管理的号池页面中，通过原有「账号状态」行的「容量异常」筛选项发现当前提供商的异常账号和发生次数。不修改请求模型，不拼接不同账号的输出，不扩大参数错误、上下文超限的重试范围，不在本次改动中扩展其他流式协议。

## 行为与配置

- 系统设置提供全局「失败自动换号」，默认开启；高级参数统一为换号次数 2、等待 5 秒、缓冲 64 KiB、模型冷却 30 秒。Responses 协议适用性由系统判断。原端点开关与参数不再决定该机制，端点界面移除重复入口。配置读取、执行和候选预算使用同一全局策略。跳过重复账号或预算耗尽时释放已获取的账号租约，预算耗尽后停止取号。
- 保持已经输出后不换号、图片生成不进入本机制的边界；全局关闭恢复原有转发行为，不关闭其他既有 HTTP 错误处理机制。
- 容量错误针对失败账号和模型暂停，不降低整个账号的协议健康分；普通限流继续按现有账号级规则处理。

## 容量记录与查询

- 复用持久化 request_candidates，每个实际尝试的唯一记录只计一次；保存标准容量标记和实际模型，避免重复日志累计计数。换号后成功不会抹去前一个账号的失败。
- 默认严格统计近 24 小时，按账号、模型聚合，展示次数、最近发生、最近记录。历史记录沿用现有请求候选保留策略，不宣称永久累计。仅容量不足及对应上游过载代码进入容量统计，普通限流不计入。
- 冷却中按服务端返回的到期时间实时显示剩余时间；冷却结束显示待验证；同账号同模型之后有成功请求才显示已恢复。清除冷却不删除统计。
- 保留现有号池页面布局、提供商选择及默认选中规则。直接在原有「账号状态」行中，与全部、可用、已失效、禁用等并列增加「容量异常 N」筛选项，沿用同一胶囊按钮样式。移除独立的「账号管理 / 容量异常」导航行；默认仍是全部账号。容量异常只查询当前提供商，展示近 24 小时次数、模型和记录，保留未恢复筛选及次数排序。
- 列表在服务端按当前提供商聚合、排序和分页。切换状态筛选时清空勾选并回到第一页；容量异常筛选下的批量操作只使用明确勾选的账号 ID，隐藏跨页全选，避免批量操作超出容量筛选范围。
- 容量筛选接入现有 URL 与会话内页面状态保存，刷新或返回号池时恢复「容量异常 / 尚未恢复」选择。URL 明确指定的筛选优先于保存状态；普通账号状态与容量筛选保持互斥，清除或切换提供商时同步清除已保存的容量筛选。

## 审查问题修复

- 目标：修复索引升级阻塞写入、数据库账号时间排序失效、容量运行状态故障拖垮列表、错误页无法退出容量筛选四处问题；不改变全局换号策略和账号状态入口位置。

- 容量统计或冷却状态查询失败时，普通账号列表继续返回，明确标记容量统计不可用；需要容量数据的筛选和排序返回可重试错误，不能使用部分结果或推断已恢复。
- 错误区域提供「清除筛选」，同步清除容量筛选及容量排序，恢复默认账号列表；查询状态保存也同步更新。
