# Codex 顶层流式错误处理

## 目标

正确处理 Codex 上游在 HTTP 200 流式响应中返回的顶层错误对象，例如 `code`、`message` 与 `data.details`。

## 非目标

- 不在网关内截断、总结或改写用户的对话和视频内容。
- 不通过更换上游账号绕过模型的上下文窗口限制。

## 行为变化

- 网关将顶层 Codex 错误识别为失败，不再记为成功完成。
- `data.details` 作为优先错误原因；无论上下游是否同为 OpenAI 格式，顶层 Codex 错误都会转换为 OpenAI 兼容的错误体。上下文超限返回 `context_length_exceeded` 和 HTTP 400。
- OpenAI Responses 流在尚未输出正文时返回 `response.failed`，网关会先解析错误，而不是直接把失败事件发送给调用方。
- `Selected model is at capacity`、`server_is_overloaded` 和 `slow_down` 按临时上游过载处理；即使上游使用 HTTP 400，网关也会尝试下一个账号。
- 发生上述临时过载后，已知模型的失败账号按“账号 + 模型”进入短暂冷却，避免其他模型一同被暂停；普通限流仍遵循账号级规则。全局开关与号池展示见 [全局失败换号与号池容量异常](global-capacity-failover.md)。
- 上下文超限属于用户请求不可重试错误，不会在多个上游账号之间重复发送。

## 影响范围

- 影响经过 OpenAI Chat 与 OpenAI Responses 格式转换的流式请求。
- 影响 OpenAI 容量错误的同步和流式账号池调度。
- 不改变模型实际可接受的上下文大小；调用方仍需在发送长对话、视频转写或大附件前控制输入规模。

## 验证方式

- 单元测试覆盖顶层 Codex 上下文超限错误的识别、HTTP 400 分类和 OpenAI 错误转换。
- 单元测试覆盖顶层错误在流式格式转换中的输出。
- 单元测试覆盖上下文超限不参与账号池重试。
- 单元测试覆盖 HTTP 400 容量错误优先切换账号。
- 流式回归测试覆盖 `response.failed` 容量错误在客户端收到正文前切换账号。
- 账号池测试覆盖容量错误触发短暂冷却。
