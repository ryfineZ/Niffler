# OpenAI Responses 实际输出前自动换号

## 目标

为 Niffler 账号池的 `openai:responses` 流式请求增加协议事件驱动的两阶段发送。上游在尚未产生文本、工具调用等实际输出时返回临时容量错误，网关应暂停当前“账号 + 模型”组合并尝试下一个账号，不把可恢复错误暴露给调用方。

## 非目标

- 不修改用户本地 Codex 配置、认证方式或模型选择。
- 不在实际输出已经发送后拼接另一账号生成的响应。
- 不重试上下文超限、参数错误、内容策略等用户请求错误。
- 不改变图片、视频、Chat Completions 和其他提供方的流式行为。
- 全局 `max_account_switches` 限制整次请求的账号切换，总账号尝试次数最多为 `1 + max_account_switches`，跨提供商仍共享同一预算。
- 不做灰度发布；通过全局开关、相关测试和可立即关闭的配置控制上线风险。

## 协议依据

OpenAI Responses 流使用带类型的 SSE 事件，消费者应按 `event.type` 分支处理。`response.created` 只表示响应对象已经创建，`response.failed` 表示生成失败；文本、函数参数等实际输出由独立事件产生。

- [Responses 流事件参考](https://developers.openai.com/api/reference/resources/responses/streaming-events)
- [迁移到 Responses：更新流消费者](https://developers.openai.com/api/docs/guides/migrate-to-responses#7-update-streaming-consumers)

## 配置

配置与管理入口已迁移到全局「失败自动换号」，完整规则见 [全局失败换号与号池容量异常](global-capacity-failover.md)。系统根据协议决定是否使用输出前检查，管理员无需选择端点。

配置保存在系统设置 `request_failover` 中：

```json
{
  "enabled": true,
  "max_account_switches": 2,
  "max_wait_ms": 5000,
  "max_buffer_bytes": 65536,
  "cooldown_seconds": 30
}
```

字段语义：

- `enabled`：一键启用或关闭，默认 `true`。
- `max_account_switches`：首次失败后最多切换的账号数量，范围 0 到 999，默认 2。
- `max_wait_ms`：从收到上游成功响应头开始，等待可提交事件的总时长；范围为 250 到 30000 毫秒。
- `max_buffer_bytes`：提交前协议检查缓冲上限，范围为 16384 到 1048576 字节；协议检查和错误记录缓冲不得超过该值。执行帧解码另设固定硬上限，防止没有换行的异常执行帧造成无界内存增长。
- `cooldown_seconds`：容量错误后暂停当前“账号 + 模型”组合的时长；范围为 1 到 1920 秒。

可重试错误继续复用网关统一失败分类，不允许端点任意扩展错误字符串。这样可以避免错误地重试上下文超限、参数错误和其他确定性失败。

## 行为变化

### 第一阶段：等待实际输出

- 网关解析完整 SSE 事件，保留原始字节和事件顺序。
- `response.created`、`response.queued`、`response.in_progress` 等只描述生命周期的事件不会立即提交给调用方。
- 收到 `response.failed` 或 `error` 时，网关提取错误对象并交给统一失败分类。
- 如果错误属于临时容量或限流，且还没有提交实际输出，当前尝试记为失败，并按全局 `max_account_switches` 选择另一个账号。启用本功能后，同一账号在一次请求中最多实际请求一次；`max_account_switches = 0` 时不自动换号，值为 `N` 时最多再尝试 `N` 个不同账号。容量错误暂停当前“账号 + 模型”组合；限流继续使用现有账号级暂停规则。
- 如果错误不可重试，立即按现有错误转换规则返回，不继续换号。

### 第二阶段：提交并正常转发

以下任一条件满足时，网关按原顺序发送全部暂存事件，并进入不可换号状态：

- 收到文本、音频、工具参数或其他实际输出 delta；
- 收到会建立输出项或内容部分的事件；
- 收到正常终止事件；
- 达到全局配置的总等待时间或暂存大小上限；
- 事件无法安全识别。

进入第二阶段后继续使用现有实时转发、用量统计和客户端断开处理。之后发生错误时只终止当前响应并记录失败，不拼接新的上游响应。

## 账号与模型级暂停

- 暂停键由提供商、上游账号和请求模型共同组成，保存在运行时状态中并带有效期。
- 调度器在返回账号前再次检查该暂停键，避免已经冻结的账号窗口继续选中失败组合。
- 模型级暂停不改变账号的 OAuth、额度或全局健康状态，不影响同一账号请求其他模型。
- 现有全账号暂停仍用于认证失效、账号封禁和通用限流等账号级问题。
- 管理端“清除冷却状态”同时清除账号级暂停和该账号仍有效的全部模型级暂停，避免界面提示成功后调度器继续跳过该账号。

## 管理界面

- 系统设置 → 网络中显示全局「失败自动换号」，号池主页面提供直达入口。
- 开关关闭时隐藏高级参数；保存后，新请求使用全局设置。
- 高级设置包括失败后换号次数、等待时间、暂存上限和模型冷却时间；不再写入端点 `max_retries`。
- 号池保持按提供商显示，在原有「账号状态」行点击「容量异常」查看当前提供商的异常账号数、近 24 小时次数、模型与发生记录，并筛选或排序。
- 输入前后端校验，保存提供处理中、成功、失败和不可用反馈。

## 监控

结构化日志至少记录：

- 两阶段发送是否启用以及最终提交原因；
- 输出提交前发现的错误代码、账号、模型和请求编号；
- 自动换号次数与最终结果；
- 模型级暂停的设置和跳过；
- 达到等待时间或暂存上限的次数；
- 实际输出后的终止错误。

日志不得记录用户提示词、完整响应正文或上游凭据。

## 影响范围

- 全局开关默认开启，影响适用的 Responses 流式请求；旧端点配置不覆盖全局设置。
- 正常请求的事件内容和顺序不变，只会延迟发送生命周期事件；首个实际输出到达后立即提交，不额外等待。
- 暂存会增加有限内存占用；等待上限和字节上限用于约束单请求资源。
- 自动换号会增加上游请求次数，失败尝试的用量仍按现有终态统计规则记录。

## 验证方式

- 配置解析测试覆盖默认开启、全局关闭、合法值、范围裁剪和非 Responses 端点不生效。
- SSE 解析测试覆盖连续生命周期事件、`response.failed`、顶层 `error`、第一个输出事件和不完整帧。
- SSE 解析测试覆盖 `response.queued` 后出现 `response.failed`，确认排队事件不会提前提交。
- 流式回归测试覆盖超过 5 个生命周期事件、等待超过 750 毫秒后容量失败仍能换号，并写入模型级暂停。
- 多账号测试覆盖 `max_account_switches = 0` 时只请求首个账号，`max_account_switches = 2` 时最多请求三个不同账号，并且不会重复请求失败账号。
- 流式回归测试覆盖参数错误不换号，以及实际输出后失败时不换号、不拼接另一账号响应。
- 调度测试覆盖模型级暂停只排除对应账号与模型组合，同一账号的其他模型仍可使用。
- 运行时状态测试覆盖一次管理端操作同时清除账号级暂停和该账号的全部模型级暂停。
- 执行帧测试覆盖硬长度上限，协议检查与错误记录缓冲不得超过全局配置值。
- 前端测试覆盖全局开关默认值、参数保存、范围校验、读取失败、保存失败及容量标记和冷却到期状态。
- 运行 Rust 格式检查、相关网关测试、前端单元测试、类型检查、UI 审查和 `git diff --check`。
