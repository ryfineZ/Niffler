# 后台手动发放套餐时间与额度设置

## 目标

后台给用户手动发放套餐时，允许管理员按真实迁移情况填写套餐开始时间、到期时间和迁移额度上限。这个能力主要用于从旧系统迁移用户，例如用户原来购买了月套餐，但剩余有效期已经不足 30 天。

## 非目标

- 不改变用户自己购买套餐的流程。
- 不改变支付成功后自动开通套餐的默认规则。
- 不新增数据库表或迁移脚本。
- 不处理已经发生的历史用量重算。

## 行为变化

- 后台打开“发放套餐”或切换套餐时，开始时间默认填当前时间，到期时间默认按所选套餐时长自动计算。
- 管理员清空时间时，套餐仍按当前时间立即生效，并按套餐原本时长计算到期时间。
- 管理员填写开始时间时，套餐的 24 小时、7 天、30 天额度周期会从这个开始时间滚动计算。
- 管理员修改开始时间后，如果没有手动改过到期时间，页面会按套餐时长重新计算到期时间；如果已经手动改过到期时间，页面不再覆盖。
- 开始时间不能晚于当前时间；如果同一个套餐已经存在未到期权益，新发放的权益会从当前到期时间后继续。
- 管理员填写到期时间时，套餐会按这个时间失效，到期时间必须晚于开始时间。
- 日期时间输入框必须同时响应键盘输入和浏览器日期选择器的选择完成事件，避免页面看起来已选择时间，但提交时仍按空值处理。
- 后台发放表单的开始时间和到期时间使用浏览器原生时间输入，提交时以输入框当前值为准。
- 按填写时间计算后已经过期的套餐不会发放，管理员需要重新填写有效的到期时间。
- 管理员填写迁移额度上限时，系统会把套餐里的正数额度上限按这个金额压低，但不会把原本更低的周期额度抬高，也不会重新计算旧系统已经用掉的额度。
- 管理员备注继续写入发放订单记录，便于之后查账。
- 套餐权益记录里的创建时间作为“获得时间”展示；后台发放和用户支付购买都会在权益实际开通时写入这个时间。

## 影响范围

- 后台用户管理里的“发放套餐”表单。
- 后台发放套餐接口。
- 套餐开通时写入的用户套餐权益记录。
- 后台用户套餐记录、资金抽屉套餐记录和用户套餐中心都会展示套餐获得时间。
- 通用输入框组件的 `datetime-local`、`date` 等浏览器选择器输入。
- PostgreSQL 与内存实现保持同一行为。

## 验证方式

- 后台接口拒绝无效时间和负数额度。
- 手动发放后，用户套餐记录显示管理员填写的开始时间和到期时间。
- 手动发放或购买成功后，套餐记录显示获得时间、开始时间和到期时间。
- 写入的套餐额度不会超过管理员填写的迁移额度上限。
- 使用浏览器日期选择器选择开始时间和到期时间后，提交请求包含对应时间。
- 不填写新增字段时，原有发放行为保持不变。
