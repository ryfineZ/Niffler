# 管理端 Codex 号池窗口用量统计

## 目标

- 修复号池管理打开 Codex 账号列表时，Postgres 为计算 5H/周用量触发全表并行扫描和共享内存申请失败的问题。
- 号池列表只读取预先维护的窗口统计，不在请求期间聚合历史用量。
- 上游额度状态与本地用量统计分开保存，避免额度刷新覆盖本地统计。
- 窗口切换期间产生的用量不会因为新窗口尚未刷新而丢失。
- 请求数、Token 和基础费用分别统计，不再以“基础费用大于零”作为共同条件。

## 非目标

- 不改变号池调度逻辑。
- 不改变账号额度耗尽判断。
- 不清理生产数据，不重启数据库，不调整数据库全局参数。
- 不在用户请求路径或号池列表路径中扫描历史用量。

## 行为变化

- `provider_api_keys.status_snapshot.quota.windows` 只保存上游额度事实，包括窗口代码、时长、重置时间和剩余比例，不再持久化本地 `usage` 或本地重置时间。
- 本地窗口统计保存到独立的 `provider_api_key_window_usage_counters` 表。
- 管理员手动重置的起算时间保存到独立的 `provider_api_key_window_usage_resets` 表，不依赖上游窗口快照是否暂时缺失或改名。
- 窗口由账号 ID、范围、代码、上游自然开始时间和结束时间共同标识；`weekly` 等代码在每次重置后会形成新的窗口记录。
- Postgres 用量队列将账号累计增量和窗口增量拆成两种记录。窗口尚未刷新时，窗口增量保持待处理，不会影响账号累计增量完成。
- 同一个窗口增量在同一个窗口只允许应用一次；部分窗口已经更新、另一个窗口尚未切换时，重试不会重复增加已更新窗口。
- 等待窗口刷新的增量会延后重试，不会反复占住队首并阻塞后续统计。
- 当前没有账号级窗口时，窗口增量直接完成；以后刷新出真实窗口时再从请求事实重建，避免无窗口账号长期堆积待处理记录。
- 额度刷新发现新窗口、缺少统计记录或统计记录尚未完成历史重建时，在后台执行一次有界重建。增量先创建的记录不能冒充已经初始化完成的记录。
- 上游暂时不返回窗口时，当前预计算结果会失效；窗口恢复后必须从请求事实重建，补回窗口缺失期间已经完成的请求。
- 重建与增量刷新使用同一个数据库互斥锁，并在可串行化事务中完成，保证并发请求不会重复或遗漏。
- 管理端主动刷新和请求响应头自动刷新都会初始化新窗口统计；自动刷新按账号和窗口身份去重，避免每个请求重复检查。
- 额度状态保存和本地统计初始化是两个独立结果。统计初始化失败只记录独立告警，不能把已经成功保存的额度误报为失败，也不能影响用户请求。
- 自动刷新初始化失败后按账号和窗口身份限频重试；同一实例 30 秒内不重复执行，避免上游响应头持续触发数据库重建和重复告警。
- 号池账号列表按当前页面账号和真实窗口读取独立统计表，不读取历史 `usage`。
- 号池列表发现当前页存在未初始化窗口时，只提交一次非阻塞后台初始化，当前响应继续显示“统计中”，不在列表请求中等待历史扫描。
- 管理端页面仅在发现“统计中”时短时重新读取当前页；统计完成后立即停止，连续数次仍未完成也停止，避免长期轮询。
- 请求数和 Token 统计已结算请求，即使基础费用为零也会统计；基础费用独立累计，允许为零。
- Provider 账号累计统计里的费用与窗口统计使用同一基础费用解析规则：只统计已结算请求的基础成本，不使用用户钱包销售金额；历史记录缺少直接基础成本时，按销售金额除以销售倍率反推基础成本。
- 管理端只显示上游实际返回的账号级窗口。不存在的 5H、周或月窗口不补充显示。
- 管理端配额栏直接遍历上游额度快照中的窗口，不使用固定窗口名单；上游返回月窗口或其他新窗口时必须同步显示。
- 窗口存在但本地统计尚未准备好时显示“统计中”；准备完成且没有用量时显示 `0`。

## 一致性规则

- `usage` 和 `usage_settlement_snapshots` 是可重新计算的请求事实来源。
- `provider_api_key_window_usage_counters` 是用于快速读取的预计算结果，不是新的计费事实来源。
- `provider_api_key_window_usage_resets` 只保存管理员本地重置边界，不保存上游额度，不参与上游剩余额度判断。
- 新请求、结算修正和账号归属修正都通过持久化增量队列更新统计。
- 窗口增量只有在所有当前相关窗口已经应用或明确过期后才标记完成。
- 尚不能完成的窗口增量会记录下次可重试时间；后台批次只读取已到重试时间的记录。
- 窗口重建会覆盖预计算结果，并登记同一事务快照中已经包含的待处理增量，后续只处理事务之后提交的增量。
- 管理员手动重置在同一个数据库互斥事务中写入独立重置边界并重建当前窗口，不改变上游窗口和上游剩余额度。
- 窗口统计结果必须带回账号、范围、代码、开始时间和结束时间，展示层按完整身份精确匹配，不能只按窗口代码匹配。

## 影响范围

- 管理端号池管理页的 Codex 账号列表。
- Provider 账号累计统计字段 `provider_api_keys.total_cost_usd`。
- Postgres 窗口统计表、手动重置边界表及增量应用记录表。
- 新建库和现有库的 Postgres 索引结构。
- Postgres 后台用量队列新增独立的账号窗口增量类型。
- Codex 额度刷新和管理员手动重置后的窗口统计初始化。

## 验证方式

- SQL 单元断言确认号池列表窗口统计只读取独立统计表。
- 打开号池管理页确认 `/api/admin/pool/{provider}/keys?page_size=50` 返回正常且耗时下降。
- 只有周窗口的账号只显示周窗口，不显示 5H。
- 同时返回 5H、周和月窗口的账号，配额栏完整显示三个窗口；新增未知窗口时也不会被前端丢弃。
- 基础费用为零的已结算请求仍累计请求数和 Token。
- 模拟旧窗口过期、新窗口尚未刷新时产生请求；刷新新窗口后，该请求只累计一次。
- 模拟额度刷新与增量任务并发执行；最终结果与请求事实重算结果一致。
- 模拟增量先创建统计记录；初始化仍会执行历史重建，不遗漏较早请求。
- 模拟上游窗口暂时消失后恢复；手动重置边界不丢失，窗口缺失期间的请求会通过重建补回。
- 模拟后台任务失败后重试；同一增量不会重复累计。
- 模拟额度保存成功但统计初始化失败；额度刷新仍返回成功，并且 30 秒内不重复初始化。
- 模拟升级前旧账号已有额度窗口但没有统计记录；第一次打开列表立即返回“统计中”，后台完成后页面短时重读并显示结果。
- 模拟同一账号存在相同代码但范围或时间边界不同的窗口；统计只写入完整身份一致的窗口。
- PostgreSQL 集成测试确认手动重置后只统计重置时间之后的已结算请求。
- 确认窗口统计不再写入持久化的 `status_snapshot.quota.windows[].usage`。
- 确认本地重置边界不再写入持久化的 `status_snapshot.quota.windows[].usage_reset_at`。
- 生产队列表索引使用 PostgreSQL 并发索引迁移，避免滚动发布时阻塞旧实例写入；创建和删除并发索引拆成独立迁移，确保每条语句都在事务外执行。
