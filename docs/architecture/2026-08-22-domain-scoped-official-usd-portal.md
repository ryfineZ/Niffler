# 按域名隔离的官方 USD 价格门户

## 目标

- 为通过专属域名注册的用户提供独立门户。
- 专属门户以 USD 展示和结算，钱包按量价格以模型官方 API 基础价为基准，默认折扣为 `1.0`，管理员可调整。
- 主站继续使用现有注册入口、公开模型目录和价格方案。
- 两个门户共用同一套网关、数据库、钱包、用量记录和管理后台。
- 注册渠道写入账号后保持稳定，用户不能通过切换访问域名改变已有账号的价格方案。
- 充值使用自动更新的支付汇率，订单创建时保存汇率快照，历史订单不随最新汇率变化。

## 非目标

- 不通过合作方 SSO、企业邮箱域名或管理员预导入名单识别用户。
- 不阻止用户使用另一个邮箱在主站重新注册；域名隔离是渠道和展示隔离，不是现实身份校验。
- 不为专属门户部署第二套数据库、钱包或结算服务。
- 不用实时汇率重算模型用量；模型用量始终以 USD 记账。
- 不按当前访问域名临时修改已存在 API Key 的折扣。

## 核心定义

### 门户

系统保留两个逻辑门户：

| 门户 | 注册入口 | 价格方案 | 展示币种 |
|---|---|---|---|
| `default` | 主站域名 | 现有默认用户组 | 现有展示规则 |
| `official_usd` | 配置的专属域名 | 专属内部用户组 | USD |

专属门户配置由服务端系统配置提供：

- `official_usd_portal_hosts`：专属域名列表，只保存主机名，不含协议和路径。
- `official_usd_portal_group_id`：专属内部用户组 ID；该组折扣由管理员维护，建议初始值为 `1.0`。
- `official_usd_portal_canonical_url`：专属门户规范访问地址。
- `default_portal_canonical_url`：主站规范访问地址。
- `official_usd_portal_site_name`、`official_usd_portal_site_subtitle`：专属门户站点文案，可选。

实时汇率配置：

- `official_usd_portal_live_exchange_rate_enabled`：是否启用专属门户自动汇率，默认开启。
- `official_usd_portal_exchange_rate_api_url`：汇率接口 URL 模板，默认使用 Coinbase 当前汇率接口；支持 `{base}` 和 `{quote}` 占位符且必须为 HTTPS。
- `official_usd_portal_exchange_rate_ttl_seconds`：成功汇率的新鲜缓存时间，默认 60 秒。
- `official_usd_portal_exchange_rate_max_stale_seconds`：接口故障时允许使用成功缓存的最大时间，默认 3600 秒；陈旧缓存会明确标记为非实时。
- `official_usd_portal_exchange_rate_timeout_seconds`：单次请求超时，默认 5 秒、最大 30 秒。
- `official_usd_portal_exchange_rate_allow_manual_fallback`：是否允许在无可用缓存时回退支付网关人工汇率，默认关闭。

反向代理必须保留对外访问域名的 `Host`，并删除客户端自行提交的 `X-Forwarded-Host`；源站不得暴露给不受信任的直连流量。应用仅使用网关收到的 `Host` 判断门户，不使用 `X-Forwarded-Host`；未知主机按默认门户处理。

### 账号门户归属

第一版不新增 `users.portal_id`。用户是否属于 `official_usd` 门户，由其是否为 `official_usd_portal_group_id` 的成员决定。

这样可以直接复用：

- 用户组成员管理；
- 内部分组不可公开选择的规则；
- API Key 分组权限；
- 分组折扣（数据库内部继续兼容 `sales_multiplier` 字段）；
- 请求结算快照。

管理员若迁移账号门户，必须同时迁移该用户现有 API Key 的绑定分组。单独增删组成员但不迁移 Key 会导致旧 Key 暂停使用或继续沿用旧方案，因此管理端后续应提供原子化的“迁移门户”操作。

## 行为变化

### 注册

1. 后端根据请求主机解析当前门户，不能接受前端提交的 `portal_id`。
2. 默认门户沿用现有默认用户组。
3. `official_usd` 门户要求 `official_usd_portal_group_id` 已配置且分组存在。
4. 专属组必须是内部分组，默认折扣和模型折扣必须是大于等于 `0` 的有限数字；配置错误时注册失败关闭，不能回退到默认组。
5. 用户、钱包、隐私政策记录、邀请关系和组成员写入任一步失败时删除新用户，避免留下半成品账号。
6. 注册响应返回门户摘要，前端用于后续页面展示。

### 登录与会话

- 登录成功前读取账号的组成员关系，解析账号所属门户。
- 当前域名与账号门户一致时正常签发会话。
- 不一致时返回 `409 Conflict`，响应包含 `portal_mismatch=true` 和 `canonical_url`，前端跳转到账号所属门户。
- `/api/users/me` 返回账号门户和计价上下文，页面不自行根据 `window.location.hostname` 推断结算规则。
- 刷新 Cookie 继续使用 host-only Cookie，不设置共享 `Domain`。

### API Key 与价格

- 专属门户用户只能在专属内部组下创建或编辑普通 API Key。
- API Key 未显式提交分组时，专属用户默认使用专属组。
- 主站公开分组不向专属用户提供，避免用户在专属门户内切换到主站价格。
- 专属组不出现在主站公开模型分组接口中。
- 用户侧模型目录返回官方基础价、实际折扣和最终 USD 价格。
- 钱包按量扣费公式保持：`模型官方基础价 × API Key 绑定分组折扣`。`1.0` 表示官方价，`0.9` 表示九折，`1.2` 表示官方价的 `1.2` 倍。
- 请求结算继续保存当时模型价格和折扣快照，价格更新不重算历史用量；数据库和内部结算链路继续使用兼容字段 `sales_multiplier`。

### 站点信息与前端

- `/api/public/site-info` 和注册设置接口按当前门户返回门户 ID、展示币种、站点名称和副标题。
- 前端金额格式化函数接收币种，不能全局硬编码 `$`。
- 专属门户的注册、模型目录、钱包、套餐和用量页面统一显示 USD。
- 登录收到门户不匹配响应时，保留用户名输入但不保留密码，跳转规范域名。

### 汇率

- 内部账本、模型基础价、钱包余额和套餐额度继续使用 USD。
- 自动汇率只用于把充值/套餐的 USD 金额换算为支付币种。
- 服务端根据登录账号所属门户选择汇率策略，而不是根据充值请求所在域名选择，避免同一账号跨域请求得到不同价格。
- 服务端在充值预览或下单时按缓存 TTL 读取汇率提供方，将最新成功结果缓存为：基础币种、支付币种、汇率、来源时间、抓取时间和来源标识。
- 创建支付订单时读取未过期缓存，并保存到订单已有的 `exchange_rate`、`pay_amount` 和 `pay_currency` 字段；来源和时间写入订单快照。
- 支付回调使用订单快照校验和入账，不读取新汇率。
- 自动汇率不可用或超过最大陈旧时间时停止创建新订单；管理员可显式切换回手工汇率模式。

## 影响范围

- 公开站点信息与注册设置接口。
- 本地注册、登录、刷新和当前用户接口。
- 用户组成员与用户 API Key 可选分组规则。
- 用户模型目录、钱包和用量金额展示。
- 支付网关配置、充值/套餐下单和支付订单快照。
- Caddy/Cloudflare 域名路由与可信转发头配置。

## 兼容与迁移

- 未配置专属门户时，所有请求保持现有默认门户行为。
- 现有用户默认属于 `default`；不会自动迁移到专属门户。
- 上线前由管理员创建专属内部组，设置需要的折扣（建议先以 `1.0` 验证），再配置门户域名和组 ID。
- 已有专属用户由管理员迁移组成员和 API Key；历史账单不修改。
- 配置发布顺序：创建组 → 部署兼容代码 → 配置域名和规范 URL → 验证 → 开放 DNS。

## 验证方式

- 单元测试覆盖主机名规范化、端口去除、大小写、未知域名和配置缺失。
- 注册测试覆盖两个门户的默认组、专属组缺失、折扣错误及失败回滚。
- 登录测试覆盖同门户成功、跨门户 `409` 和规范 URL 响应。
- API Key 测试覆盖专属用户只能使用专属组，主站用户不能越权绑定专属组。
- 模型目录测试覆盖专属门户最终价格为官方价乘实际折扣，并允许折扣高于 `1.0`。
- 汇率测试覆盖缓存命中、过期拒绝、手工回退、订单汇率冻结和回调不重算。
- 前端类型检查和相关组件测试覆盖门户上下文、USD 格式化及跨门户跳转。
- 生产验证分别使用两个固定 Host 请求站点信息、注册、登录、模型目录、充值预览和一笔最小金额支付订单。

## 已知边界

- 不做现实身份校验时，无法阻止用户使用另一个邮箱在价格更低的主站重新注册。
- 专属门户提供相同底层模型但价格更高时，应通过渠道协议、服务范围或页面说明明确价格口径，避免把域名隔离误解为安全边界。
