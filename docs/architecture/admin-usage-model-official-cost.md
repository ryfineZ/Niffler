# 使用模型统计官方应扣

## 目标

“按模型分析”和用户详情里的模型统计增加“官方应扣”列，用来展示按模型官方基础价计算出的应扣金额，避免把“平均扣费/M token”误解为基础价格或用户实际扣费。

## 非目标

- 不改变钱包扣费、套餐扣费、平台成本和请求结算逻辑。
- 不重算历史记录。
- 不改变成功请求本身的 token 计算规则。

## 行为变化

- `/api/admin/usage/aggregation/stats?group_by=model` 返回 `official_cost`。
- `/api/users/me/usage` 的 `summary_by_model` 返回 `official_cost`。
- 前端模型统计表显示“官方应扣”、“用户实扣/平台成本”和“平均实扣/M”。
- “官方应扣”来自结算基础价汇总，不使用前端倍率倒推。
- Postgres 日统计表新增 `official_cost`，迁移只加列；旧日统计在查询时回退显示已有 `total_cost`，后续统计重建任务会写入真实基础价。
- 使用记录聚合里的 token、缓存读写、官方应扣、用户实扣和平台成本只统计成功完成的请求；取消、失败和入口拒绝请求仍计入请求量、错误量和成功率，但不参与缓存命中率分母。

## 影响范围

- 影响管理端和用户端共用的模型统计组件显示。
- 后端聚合结构增加字段，内存与 PostgreSQL 仓库保持同名字段。
- Postgres 迁移只更新三张日统计表，不扫描原始请求表，避免上线时压数据库。
- 取消请求里由请求体估算出的 input token 不再拉低模型、上游或 API 格式维度的缓存命中率。

## 验证方式

- 后端接口测试覆盖模型聚合返回 `official_cost`。
- 后端接口测试覆盖取消请求不参与缓存命中率和 token 汇总。
- 前端单测覆盖模型统计保留 `official_cost`。
