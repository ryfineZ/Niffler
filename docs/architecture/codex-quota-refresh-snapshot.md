# Codex 配额刷新快照保护

## 目标

避免 Codex 管理页和号池调度使用不存在或已经过期的配额窗口，尤其是账号已经没有 5H 限额时仍然显示 5H。

## 非目标

不改变 Codex 账号授权、调度策略、计费口径和窗口用量统计方式。

## 行为变化

Codex 配额窗口只在存在上游数据证据时生成：

- `wham/usage` 响应中本次实际返回的窗口，才可以生成完整的 5H、7D、1M、Spark 或其他窗口集合。7D 窗口内部继续使用 `weekly` 标识。
- 普通模型请求的 `x-codex-*` 响应头只更新账号级普通窗口；响应头没有 Spark 和主动重置次数字段时，必须保留最近一次完整额度刷新得到的对应数据。
- 付费计划本身不再作为生成 5H 窗口的依据。
- 完整额度刷新明确返回了其他账号级窗口但没有返回 5H 时，清除旧快照和旧 metadata 中残留的 5H；普通模型响应头同样可以替换账号级窗口集合，但不能清除 feature 窗口。
- 本次没有任何当前配额窗口数据时，不显示历史窗口，页面显示“暂无上游配额数据”；历史窗口只允许用于独立的本地用量统计，不能冒充当前上游额度。
- 402 额度耗尽 fallback 只记录“额度耗尽”状态，不伪造周度或 5H 的具体窗口。

## 影响范围

影响 Codex provider key 的 `upstream_metadata`、`status_snapshot.quota.windows`、管理页配额展示和号池额度耗尽判断。正常业务请求返回头仍会继续更新真实窗口；不存在窗口时不再用固定 5H 数据代替。

## 验证方式

运行 Codex 配额解析、管理刷新、响应头同步和号池快照相关测试，至少确认：

- 只有月度/周度窗口时不会出现 5H。
- 新数据没有 5H 时会清除旧的 5H。
- 普通模型响应头更新周额度后仍保留 Spark 窗口和主动重置次数。
- 无窗口的身份或非配额响应不会继续展示历史窗口。
- 402 额度耗尽不会生成虚假的 5H 窗口，但仍会阻止继续调度。
