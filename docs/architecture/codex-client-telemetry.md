# Codex 客户端遥测实验

## 目标与非目标

为 Niffler 管理员提供默认关闭的 Codex OAuth 客户端遥测开关，验证分析事件和 OTLP 指标能否正常上报，并通过固定账号、模型、推理档位和题集对比开关前后的回答结果。

参考 codex2api PR #666 的独立分析事件与 Statsig OTLP 上报方式。按用户确认复现原 PR 的模拟方案：动态工具每轮 40%，其中 50% 同时模拟命令执行；文件修改每轮 20%，同时发送 accepted fingerprints（repo_hash=null）；每轮四个 hook，首次线程模拟标题任务，每轮模拟 guardian 初始化。覆盖原 PR 的 66 个指标名，启动指标包含模拟值。请求状态、用量与主要耗时采用真实观测。所有随机事件只用于遥测，不实际执行命令、修改文件或调用子模型。不保证遥测改变模型能力，也不退出或重置账号登录会话。

## 配置与行为

- 系统配置 `codex_telemetry_enabled` 为布尔值，默认 `false`；复用 system_configs，无数据库迁移。入口为系统设置的 Provider 高级设置。
- 环境变量 `CODEX_TELEMETRY_ENABLED=false`（也接受 0/no/off）强制关闭。管理端开关不会覆盖部署级关闭。
- 仅对发往 HTTPS `chatgpt.com` 官方 Codex 普通 Responses、携带 Bearer 和 ChatGPT 账号身份的请求生效。排除 Compact、明确的图片请求和第三方地址；普通文本请求即使声明或由 Niffler 自动附加 `image_generation` 工具，仍参与遥测。图片请求依据图片接口、图片模型或显式生图 `tool_choice` 判断。
- 复用最终出站账号、User-Agent、originator、会话和回合身份，以及原请求的代理/隧道和传输配置。遥测单独白名单构造请求头，禁止重定向，超时十秒。
- 分析事件发往 `https://chatgpt.com/backend-api/codex/analytics-events/events`；指标发往 `https://ab.chatgpt.com/otlp/v1/metrics`。指标请求仅携带公开 Statsig SDK key，不携带 OAuth 凭证。
- 遥测不包含输入提示词、回答正文、命令内容或文件内容；只包含身份元数据、模型、状态、用量和耗时。
- 后台任务并发有界，满载丢弃，发送失败只记录类别和 HTTP 状态，不影响用户响应，不记录令牌。关闭后停止新观测和未开始的上报；已发出的请求允许在超时内结束。
- 启动批次覆盖 62 个指标名，每账号/出口/传输指纹的增量指标每 60 秒合并发送；每批最多 1 MiB。每个请求分别保留观测值和模型属性，避免参考实现多轮直方图相加、跨模型标签混淆的问题。取消或没有收到明确终态的响应不报成功。完整 JSON 响应按 JSON 解析，支持末尾换行和格式化换行；直连、隧道及缓冲读取错误统一记为失败，不标记为客户端主动中断。

## 影响范围与验证

仅改动管理配置和界面、网关同步及流式上游执行观测。关闭时不改写模型请求，不发送额外网络流量。

自动验证覆盖默认关闭、非法配置、精确目标地址、普通文本生图工具声明与明确生图请求的区分、凭证隔离、完整 JSON 终态、分块流终态、取消/错误、不同模型指标独立、重定向禁止、代理继承和界面加载/保存异常。真实测试分开记录遥测接口返回和题集正确率、完成率、耗时、推理用量；小样本不用于宣称恢复能力。

## 对照脚本

`scripts/oneoff/verify_codex_telemetry.py` 面向隔离测试实例，凭证只通过 `NIFFLER_TEST_ADMIN_TOKEN` 传入，入口通过 `NIFFLER_TEST_BASE_URL` 传入，设备标识通过与令牌绑定的 `NIFFLER_TEST_DEVICE_ID` 传入。显式指定 `--provider-id`、`--key-id`、`--model`、`--effort`、`--output`；脚本固定账号和参数，关闭与开启各测试六道可程序验证的题目。开启组先预热并等候指标刷新，结束或中断时恢复原开关。输出记录客观评分、完成状态、用量和耗时，不保存令牌。

上报结果另从网关 `codex_telemetry_delivery` 日志核对 HTTP 状态；脚本正确率不能代替上报验收。由于是同账号先后对照，小样本、缓存、时间顺序和可能的账号状态残留都限制因果结论。
