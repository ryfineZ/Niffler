# State 可视化与请求结果判定

## 目标与范围

面向管理员，在 Provider 管理主页面直接查看 Codex 账号的 state 是否可用、最近采集结果、最近正式请求是否注入，点开账号可看各模型、出口的明细。请求记录以最终执行状态为准，HTTP 200 不能覆盖明确的失败状态。

不修改 state 筛选、调度、冷却或计费规则；不把“未取得合格 state”显示成账号不可用；不保存或返回 state、认证信息和用户正文。历史请求不批量改写。

## 行为变化

- 列表的显式 `failed` 始终展示失败，即使流式连接已返回 HTTP 200。显式 `completed` 继续代表请求最终成功，避免把重试前的历史错误当成最终失败。
- 流式输出开始后仍持续识别 Responses 的 `response.failed` 和结构化 `error`。将错误交给客户端后，候选、请求记录及账号容量状态必须走现有失败处理，不能在 EOF 时写成功。已输出内容不换账号重放，不重复追加同一错误。识别独立于正文留存开关，并支持事件跨数据块。
- Codex 账号提供只读 state 状态面板，支持刷新，展示各模型/出口最近观测、采集拒绝原因、实际缓存有效性和最近正式派发方式。无观测、关闭、冷却、认证拒绝和读取失败分别表达。
- 诊断元数据通过共享运行状态跨应用实例读取，按账号限制条目数及保存时间；接口仅限已有管理员 Provider 权限。缓存可用性须在读取时核验，配置或凭据变化后不能显示旧 state 为可用。
- 观测写入有时间上限且只影响诊断，失败写日志，不能因为面板数据保存失败阻断正常请求。正式请求使用记录仅表示已经派发并取得响应头，不表示生成成功。

## 证据与验收

线上存在 `status=failed/status_code=200/billing_status=void` 的连接中断记录，前端现有 helper 会将其显示为成功。用户报告的容量不足样本仍需请求 ID 对照；此前尝试失败而最终重试成功的请求必须保留成功状态。

先通过失败测试复现 HTTP 200 覆盖 failed，再验证列表与时间线一致、重试最终成功、活动中和取消状态。诊断验证缓存过期/撤销、配置变化、双实例隔离、敏感字段不外泄、关闭/无数据/读取失败。前端完成类型检查、相关组件测试及实际面板查看。

## 实现与验证记录

- 已复现：`response.failed` 被转发后，原后端会写 `completed`。增加独立、有界的流式错误观察器，跨数据块解析结构化错误，不以正文关键词判定失败。错误回包进入现有失败归档与容量冷却逻辑，不重放已输出请求，不重复追加错误事件。
- 主入口为 Provider 管理顶部的 Codex State 账号总览；原 Codex Provider 抽屉内账号右侧「State 状态」保留为明细快捷入口。单账号只读接口为 `GET /api/admin/providers/{provider_id}/turn-state?key_id=...`，沿用 `admin:providers` 权限，并校验账号归属。
- 共享诊断按账号最多保留 24 个模型/出口组合、24 小时；正式请求最多等待诊断写入 250ms，超过等待窗口后由有界后台任务继续完成，任务总时限为 3 秒、每实例最多并发 64 个。读接口不触发探测。面板提供刷新后的状态快照，直连按应用实例区分；采集完成与实际注入分别显示。缓存消失或被撤销后不继续标记可用，凭据或配置变化后显示旧观测已失效。
- 浏览器已实测桌面 1280×720、手机 390×844，以及加载失败后重试、无观测、关闭功能和关闭面板。使用隔离演示数据，未伪装成线上账号结果；临时浏览器和服务已关闭。
- 常规前端构建通过。额外运行 `vue-tsc -b` 得到 20 处现有类型错误；在原始 HEAD 的临时副本中复现同样错误，本次没有新增。项目原 `type-check` 脚本不覆盖完整 project references，不能把其通过等同于完整类型检查通过。
- 历史误记成功的请求缺少可直接复核的错误正文，未批量修改历史状态或账单。修复只保证新经过该路径的结构化失败正确归档；不改变上游容量本身。

## 上线后的诊断写入补正

- 首次上线核查在 OVH 发现诊断写入失败且没有账号观测条目。实测 Redis 单次命令往返约 25ms，现有运行状态实现每次操作新建连接，注册还串行执行配置读取、加锁、读取、发布和释放；原 250ms 覆盖整条链路，会取消尚未完成的注册。
- 将请求等待窗口与写入完成期限分开：等待超时不取消写入，后台任务仍有总时限和并发上限；只持有必要的诊断元数据及配置快照，不复制请求正文。实际写入错误、后台超时、并发已满分别记录原因。
- 验收：以受控延迟复现超过前台等待窗口的写入，确认请求等待已经结束后诊断任务仍能完成；诊断测试 9 项、架构检查 167 项及 Clippy 均通过。上线后继续核查两台服务器的真实共享存储写入。

## State 入口与账号总览调整

- 主入口改为 Provider 管理页面顶部的「Codex State」账号列表，直接显示账号、Provider、当前可用情况、最近采集原因、最近正式请求是否注入及时间；无需先打开 Provider 抽屉。原账号详情入口保留为快捷明细。
- 支持按账号或 Provider 名称搜索、分页和手动刷新。列表覆盖全部 Codex OAuth 账号，包含未启用账号与没有观测的账号，不受下方 Provider 表格当前分页和筛选影响。首次无账号时不占页面空间；接口失败必须显示重试入口，不能伪装成无账号。
- 新增只读 `GET /api/admin/providers/turn-state?page=1&page_size=10&search=...`，沿用 `admin:providers` 权限。每页最多 20 个账号，只读取当前页的诊断，每次请求最多 4 个账号并行，每个账号读取最多 5 秒；失败账号独立标注「读取失败」，不影响其他账号展示。不增加自动轮询或触发采集。
- 多模型、多出口的可用数显示为「可用组合 / 已观测组合」，不得把部分可用说成全账号正常。认证拒绝和限流单独提醒；最新采集与最新派发分别按各自时间选择，并标明模型。已关闭、无观测、配置变化、未采到均明确表达；未注入不等于账号或请求失败。
- 验收覆盖分页/搜索、非 Codex 与非 OAuth 排除、只读与敏感信息不外泄、单账号读取失败、过期响应不覆盖新搜索、桌面与手机实际显示及从总览直接打开明细。
- 已验证：State 相关后端测试 69 项、总览分页/搜索/损坏记录隔离测试、架构检查 167 项与 Clippy 通过；前端相关组件测试 9 项、构建和新增生产代码 ESLint 通过。完整类型检查与既有基线一致，仍存在原有 20 处错误。使用隔离演示数据实际检查 1440×1000、390×844、搜索无结果、读取失败后重试和明细开关；没有拿演示结果冒充线上状态。
